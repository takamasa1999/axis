# Quickstart: ローカル検証と動作確認

**Plan**: [plan.md](./plan.md)

001 の [quickstart.md](../001-phase1-career-dialogue/quickstart.md) のセットアップ（Docker Compose・マイグレーション・シード）を前提とする。

## セットアップ

```bash
docker compose up -d              # PostgreSQL と Mailpit
npm install
npm run db:migrate                # 002 のマイグレーション（pg_trgm の有効化を含む）
npm run db:seed                   # 運営アカウント、サンプルの企業・求人・求職者
npm run dev                       # http://localhost:3000（バックグラウンドのジョブも同時に起動）
```

- `.env.local` に `MESSAGE_ENCRYPTION_KEY`（メッセージの暗号化の鍵）が必要。`.env.example` の説明に従って作る
- 届いたメール（確認メール・パスワードの再設定・新着の通知）は Mailpit（http://localhost:8025）で確認する
- サンプルのアカウントとパスワードは `prisma/seed.ts` と `.env.example` に記載する

## シナリオ1：企業が求人を出す（US1）

1. `/signup` で「人を探している（企業）」を選び、メールアドレスとパスワード（8文字以上）で登録する
2. Mailpit の確認メールのリンクを開く → 企業プロフィールの入力に進む
3. `/employer/jobs/new` で求人を作る
   - **確認**：必須の労働条件を1つ空けると公開できず、足りない項目が示される（FR-009）
   - **確認**：本文に「女性歓迎」と書くと公開できず、言い換えが提案される（FR-011）
   - **確認**：年齢の条件は、例外理由を選ばないと入れられない（FR-012）
4. 全部を埋めて、3つの確認にチェックして公開する
   - **確認**：ログアウトした状態で `/jobs/[id]` を開くと、掲載日・最終更新日・企業名が表示される（US1）

## シナリオ2：求職者が探して応募し、メッセージでやり取りする（US2・US3）

1. ログアウトした状態で `/` → `/jobs` で勤務地と雇用形態を絞り込む
   - **確認**：並び順は「新着順」「給与の高い順」だけ（FR-019）
2. 求人の「応募する」→ 登録（求職者、18歳以上の確認）→ 確認メールのリンク → 元の求人に戻る
3. 共有するプロフィール項目を選び、企業に見える内容を確認して応募する（FR-022）
4. 別のブラウザ（またはシークレットウィンドウ）で企業としてログインし、`/messages` で応募を確認して返信する
   - **確認**：求職者の画面に5秒以内に返信が表示される（SC-005）
   - **確認**：求職者が画面を閉じていれば、5分後に Mailpit に新着のメールが届く（FR-026）
5. 企業が求人の賃金を変える
   - **確認**：求職者の会話に「労働条件が変更されました」のお知らせが届く（FR-015）

## シナリオ3：求職の投稿と声かけ（US4）

1. 求職者が `/me/posts/new` で投稿を作り、本文に電話番号を書く
   - **確認**：公開前に「連絡先は書かないでください」と注意される（FR-033）
2. ログアウトした状態で `/seekers` を開く
   - **確認**：見られない（ログインした企業だけ。FR-032）
3. 企業でログインし、`/seekers` から投稿を開いて声をかける → 求職者に会話が届く

## シナリオ4：通報と運営の対応（US5）

1. 求職者がメッセージを2件選んで通報する
2. 運営（シードの運営アカウント）で `/ops/reports` を開く
   - **確認**：通報で選ばれた2件のメッセージだけが表示され、会話の残りは見られない（FR-027, SC-007）
3. 求人を通報し、運営が「修正依頼」→ 期限切れ → 「非公開」にする
   - **確認**：運営の画面から求人の内容を編集する手段がない（FR-016）
4. `/ops/metrics` で期間を指定し、掲載した求人の数・登録した求職者の数が出る（FR-038）

## シナリオ5：アカウント（US6）と Axis エンジン（US7）

1. `/login` でパスワードを10回間違える → ロックされ、Mailpit にお知らせが届く（FR-004）
2. `/forgot-password` から再設定 → 新しいパスワードでログインできる（FR-005）
3. 求職者で `/axis` を開く → 利用権がないので紹介が表示される。運営が `/ops/entitlements` で利用権を付けると、001 の対話が使える（US7）

## 自動テスト

```bash
npm run lint
npm run typecheck
npm test                    # 単体・結合（掲載ルール・メッセージの暗号化・回数制限・状態遷移）
npm run test:contract       # アクセス権の表（001 と 002）
npm run test:e2e            # Playwright（シナリオ1〜4）
```

**期待する結果**：すべて成功する。特に、`test:contract` で運営が会話を読めるケースが1件もないこと、
`npm test` の掲載ルールのテストで必須項目・性別・年齢のルールがすべて守られていること。
