# Axis Constitution

## Core Principles

### I. 本人主体（Person-Centered）

- キャリア形成の主体は常に本人である。すべての機能は「本人にとっての価値」を最初に評価する。
- 本人に価値がない機能は、企業・紹介会社にとって価値があっても採用しない。
- 事業の入口は、求職者と人を求める企業が気軽に使える求人・求職の掲示板とする（2026-10-04 方針転換）。
  掲示板も「企業のための応募者管理ツール」ではなく、本人が自分で選び、自分のキャリアを積み上げる場として設計する。
- Axis エンジン（AI との対話・判断の履歴の蓄積など）は、掲示板の上に載る追加機能として位置づける。

**Rationale**: 本人に価値がなければ、企業・紹介会社への価値も成立しない。入口を広げても、中心に置く価値は変えない。

### II. AIは答えを決めない（No Answers, Only Material & Questions）

- AIの出力は「考える材料（過去の判断軸との比較など）」と「問い（見落としている観点など）」の
  2種類に限る。
- AIは本人の代わりに選ばない。転職すべきかを判定しない。正解を1つに絞って示さない。
- 「今は転職しない」も、深く考えた結果として正しい選択肢の1つとして扱う。
  転職・応募へ誘導する表現や設計は禁止する。

**Rationale**: 答えを持つのは本人であり、Axisは本人が自分で選べる状態をつくる。

### III. 判断の過程を時間軸で蓄積する（Longitudinal Decision History）

- Axisの中心は経歴（結果）ではなく「どう考え、どう変わったか」の記録である。
- 記録は節目（就職・転職・昇進/異動・学び直し・人生の変化）ごとに時点付きで残し、
  後から過去の自分の判断と比較できなければならない。
- 利用頻度（毎日使われること）を成功指標にしない。節目に「戻ってくる場所」であることを目指す。

**Rationale**: 履歴書には「なぜ選んだか」が残らず、自己分析が毎回ゼロからになる。

### IV. 共有は本人の確認と許可が前提（Consent-Gated Sharing）

- 本人の情報を第三者（企業・紹介会社・学校・勤務先など）へ渡すときは、
  本人が内容を確認し、共有範囲を選び、明示的に操作した後に限る。既定値は「共有しない」とする。
- 掲示板では、本人が自分で公開した投稿、本人が自分で応募・送信したメッセージだけが相手に届く。
  運営が本人の情報を本人の操作なしに企業へ渡すことはしない。
- Axis エンジンの対話の全文など、本人が選んでいない情報は渡さない。

**Rationale**: 共有の可否を決める主体は常に本人である。

### V. 本人のAxisは本人に残る（Person-Owned Data, No Lock-in）

- 支援者・企業との関係が終わっても、本人のAxisは本人に残り続ける。
- 第三者へ共有済みの情報は、その第三者の範囲で扱われる。本人側の記録は削除・縮退しない。
- Axisは企業の求職者データベースになることを目的にしない。
  データの囲い込みを競争優位にしない。データを本人の同意なく企業資産化しない。

**Rationale**: 支援者が変わっても履歴が途切れないことが、長期構想の土台になる。

### VI. 利益のために本人主体を壊さない（Integrity over Revenue）

- 利益は事業継続の条件だが、本人の主体性を損なう利益であれば、その事業・機能は選ばない。
- 掲示板の基本機能（閲覧・投稿・応募・メッセージ）は、求職者・企業ともに無料とする。
- 有償の追加機能（サブスク）は、無料の基本機能を使いにくくして誘導する設計にしない。
- 求職者から、求人情報の提供や応募に関して、いかなる名義でも料金を受け取らない（職業安定法第43条の3・同指針）。
  求職者向けの有償機能を設ける場合は、法務確認でこの規定に抵触しないと確認できるまで提供しない。

**Rationale**: 成功報酬や課金の都合で、本人の選択がゆがめられてはならない。

### VII. 法令遵守（職業安定法・電気通信事業法）

- Axis は「募集情報等提供事業」として運営し、許可が必要な「職業紹介（あっせん）」を行わない。
  次の行為は、有料職業紹介事業の許可を得るまで設計・実装しない（職業安定法の指針 第五の六）：
  - あらかじめ明示した客観的な条件によらず、運営の判断で求職者・求人の情報を選別・加工して提供すること
  - 運営から求職者に求人を、企業に求職者を連絡・推薦すること（運営によるスカウト・紹介）
  - 求職者と企業のメッセージを中継するときに、その内容を加工すること
- 推薦・並び替え・AI による提案は、利用者が自分で設定した条件、または事前に公開した客観的な基準に基づくものに限る。
- 求職者の情報を集めて提供するため、公開前に「特定募集情報等提供事業」の届出を行い、事業概況報告を続ける。
- 求人には、業務内容・就業場所・賃金・労働時間など法令で求められる労働条件の明示を求め、
  情報を正確かつ最新に保つ仕組み（掲載日・更新日・掲載終了）を持つ。
  法令違反・公衆衛生や公衆道徳上有害・実際と異なる求人は、修正を依頼し、応じなければ掲載しない。
  運営は企業の承諾なしに求人内容を改変しない。
- 性別による募集の区別、法令の例外によらない年齢制限など、差別的な募集をさせない。
- 利用者間のメッセージは「他人の通信の媒介」にあたるため、公開前に電気通信事業の届出を行う。
  運営はメッセージの内容を見ない（通信の秘密）。通報を受けた場合に、通報者が提出した範囲だけを確認する。
- 苦情・相談の窓口を明確にし、迅速に対応する体制を持つ。

**Rationale**: 本人と企業が安心して使えることが前提であり、違法な状態での公開は事業そのものを失う。

### VIII. 誰でも始めやすい（Easy for Everyone）

- 初めての人でも、説明を読まずに迷わず使える画面にする。専門用語を使わず、やさしい日本語で書く。
- 見るだけならログイン不要。登録はメールアドレスとパスワードだけで始められる。
- スマートフォンで使いやすいことを前提にする。見た目はポップで親しみやすく、それでも情報は正確に読める。
- 認証の強化（多要素認証など）は将来の追加機能とし、追加しても既存の利用者が始めにくくならない形で入れる。

**Rationale**: 掲示板は人が集まって初めて価値が出る。始めにくさは、そのまま人が集まらない理由になる。

## プライバシー・データ取扱い要件

- 個人の情報は機微情報として扱う。収集は提供価値に必要な最小限とする。
- 研究・統計利用（長期構想）は、本人同意と匿名化を前提とする。同意のない二次利用は行わない。
- 本人は自分の記録をいつでも閲覧・修正・削除・持ち出しできなければならない。
- 共有・許可・取り消し・公開・非公開の操作は、後から本人が確認できる形で記録する。
- 求職者の個人情報は、職業安定法の指針（第四）に沿って、目的の範囲で収集・保管・使用する。
- 利用者間のメッセージの内容は、通報への対応など利用者の同意がある場合を除き、運営が閲覧しない。

## 検証駆動の開発プロセス

- 仕様・計画では、内容のステータス（方針／仮説／外部調査／仮置き／判断基準案／未決／長期構想）を
  区別して記述する。仮説や仮置きの数値を確定事項として扱わない。
- 検証で必要と分かった機能だけを作る。
  初期から大規模な外部システム連携は作らない（CSV・コピーしやすい形式・必要最小限の連携から始める）。
- 撤退・見直しの判断基準を、検証を始める前に数値で決める。
- 支払い意思の証拠がない段階で、大きな固定費を前提とした開発計画を立てない。
- 法令に関わる機能（求人の掲載ルール、メッセージ、推薦、有償機能）は、公開前に法務確認の要否を仕様に明記する。

## Governance

- この Constitution は、Axis のすべての仕様（spec）・計画（plan）・タスク（tasks）・実装に優先する。
- `/speckit-plan` の Constitution Check では、原則I〜VIIIへの適合を必ず判定する。
  違反がある場合は、理由と代替案の検討を Complexity Tracking に記録し、創業メンバーの合意を得る。
- 原則VII（法令遵守）に関わる判断は、創業メンバーの合意に加え、必要に応じて専門家（弁護士・社会保険労務士など）の確認を得る。
- 改定は創業メンバー3名（Founder / Engineer / Solution Sales・AI Engineer）の合意で行い、
  改定理由と影響範囲を Sync Impact Report に記録する。
- バージョンはセマンティックバージョニングに従う。
  MAJOR：原則の削除・再定義／MINOR：原則・節の追加や大幅な拡張／PATCH：表現の明確化・誤字修正。
- 事業構想資料の改版や方針転換があった場合は、この Constitution の改定要否を確認する。
